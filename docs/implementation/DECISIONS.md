# 决定记录

## 1. 用途

本文件记录执行期间会影响架构、契约、依赖、安全、数据迁移、部署或验收方法的决定。执行者不得在普通代码改动中静默改变这些内容。

决定记录是设计依据，不是任务状态来源。任务状态只在 `EXECUTION_STATE.md` 中维护。

## 2. 何时必须新增决定

出现以下情况之一时必须先新增决定，再继续实现：

- 更换或新增框架、数据库、向量存储、Provider 或关键依赖；
- 修改 API 字段、错误格式、状态机、页码口径或 Citation 契约；
- 改变密钥存储、日志脱敏、文件存储或删除策略；
- 改变同步/异步处理方式、事务边界或重试语义；
- 因环境限制采用与既定架构不同的替代方案；
- 接受一个会影响后续任务的已知限制；
- 跳过、替换或降低原定验收方式。

局部变量命名、等价内部重构和不改变行为的小修复通常不需要决定记录。

## 3. 状态和编号

决定编号使用 `D-0001`、`D-0002` 递增，不重复使用。

允许状态：

- `PROPOSED`：已提出，尚未获准用于实现；
- `ACCEPTED`：已接受，可作为后续约束；
- `REJECTED`：明确不采用；
- `SUPERSEDED`：已被新决定替代。

不得直接改写历史决定来隐藏变化。需要改变已接受决定时，新增一条决定并在双方记录中写明替代关系。

## 4. 已接受的治理决定

### D-0001：执行状态使用单一来源

- 状态：`ACCEPTED`
- 日期：2026-08-22
- 关联任务：治理文档初始化
- 背景：较弱模型容易依据聊天、任务卡和计划中的重复状态产生冲突。
- 决定：`EXECUTION_STATE.md` 是阶段和任务动态状态的唯一来源；其他文件不得保存动态任务状态。
- 影响：每次任务转换必须原子更新当前指针、任务行、阶段摘要和证据。
- 验证：状态更新检查必须确认最多一个 `IN_PROGRESS`。

### D-0002：一次只执行一个原子任务

- 状态：`ACCEPTED`
- 日期：2026-08-22
- 关联任务：治理文档初始化
- 背景：跨层并行实现容易造成契约漂移、混合 diff 和无法恢复的中间状态。
- 决定：任意时刻最多一个任务为 `IN_PROGRESS`；范围外发现转为后续任务或失败记录。
- 影响：测试等待期间也不得切换到其他任务。
- 验证：任务开始和结束均检查状态表与工作树。

### D-0003：任务提交仅限本地且仅包含当前范围

- 状态：`ACCEPTED`
- 日期：2026-08-22
- 关联任务：治理文档初始化
- 背景：本地 checkpoint 有利于上下文恢复，但自动推送或混入其他改动会扩大风险。
- 决定：验证通过后可创建当前任务的本地 checkpoint commit；仅精确暂存当前任务文件；不得自动 push、rebase、squash 或重写历史。
- 影响：每次交接记录 SHA；无提交时必须写明原因。
- 验证：提交前后检查 `git status --short` 和提交文件列表。

### D-0004：连续失败停止盲目重试

- 状态：`ACCEPTED`
- 日期：2026-08-22
- 关联任务：治理文档初始化
- 背景：能力较弱模型容易对同一错误重复相同命令或进行无证据修改。
- 决定：同一错误连续两次没有实质进展，或单任务累计三次仍未通过时，将任务标记为 `BLOCKED` 并升级。
- 影响：升级前必须记录最小复现、错误原文、不同假设、当前 diff 和解除条件。
- 验证：`FAILURE_LOG.md` 中有完整尝试链，状态文件关联失败编号。

## 5. 新决定模板

复制以下模板追加，不要覆盖既有条目：

```markdown
### D-NNNN：决定标题

- 状态：`PROPOSED | ACCEPTED | REJECTED | SUPERSEDED`
- 日期：YYYY-MM-DD
- 决策者：用户 / 执行者 / Review
- 关联任务：Pxx-Txx
- 关联需求：REQ-...
- 替代或被替代：D-NNNN / NONE

#### 背景

描述触发决定的事实、约束和可复现证据，不写猜测。

#### 决定

明确写出采用什么，以及边界是什么。

#### 备选方案

1. 方案 A：未采用原因。
2. 方案 B：未采用原因。

#### 影响

- 代码与文件：
- API/数据契约：
- 安全与隐私：
- 测试与部署：
- 后续任务：

#### 验证与回退

- 验证命令或证据：
- 可回退条件：
- 回退方法：
```

## 6. 决定审查清单

- [ ] 决定由可验证事实触发，而不是个人偏好
- [ ] 没有违背用户明确要求
- [ ] 安全、迁移和兼容性影响已说明
- [ ] 替代方案和不采用理由已记录
- [ ] 相关任务卡、契约和状态已关联
- [ ] 没有把临时环境故障永久固化为产品架构
