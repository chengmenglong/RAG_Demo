# P04：文档存储与上传生命周期

阶段目标：先把上传安全、元数据和状态做正确。此阶段只将文档置为 `pending`，不伪造解析完成。

## P04-T01：实现 Document 模型、状态机与迁移

- **需求**：DOC-05、DB-02、KB-02
- **前置**：P03 Gate。
- **结果**：文档记录可追踪知识库、原名、存储键、类型、大小、SHA-256、状态、阶段、错误和时间。
- **允许文件**：`models/document.py`、schema/repository 基础、KnowledgeBase 关系、一个迁移、测试。
- **实现**：完整字段以 `03_API_DATA_CONTRACTS.md` 为准，含 attempt_count、parser_name、chunk 配置快照、embedding profile hash、提取字符数和 chunk 数；状态 `pending/processing/ready/failed`；阶段按契约；同库 `(knowledge_base_id, sha256)` 唯一；状态转换由显式方法校验。
- **验证**：迁移、唯一约束、级联、合法/非法转换、Dashboard 文档聚合补测。
- **负向**：`ready/completed` 必须要求 `chunk_count>0`、`extracted_char_count>0` 和非空 profile hash；不得从 `failed` 直接改 ready。
- **完成门**：上传成功与解析成功在模型上明确分离。

## P04-T02：实现本地 FileStorage 和安全路径

- **需求**：STORE-01、SEC-02、DOC-03
- **前置**：P02-T01。
- **结果**：客户端文件名永远不会成为磁盘路径；文件只写入配置的数据根内。
- **允许文件**：`storage/base.py`、`storage/local.py`、`utils/files.py`、测试。
- **实现**：storage key 为 `{kb_uuid}/{doc_uuid}{normalized_ext}`；流式 `.part` 写入、SHA-256、原子 rename；所有 resolve 后路径检查根目录；接口含 open/delete/exists。
- **验证**：Unicode、同名、`../`、绝对路径、反斜杠、保留名测试；写入后 hash/size 正确。
- **负向**：任何逃逸根目录的 key 必须在触盘前失败；删除不存在文件幂等。
- **完成门**：数据库只存相对 key，不存主机绝对路径。

## P04-T03：实现四格式、大小、空文件与内容签名验证

- **需求**：DOC-01、DOC-03、SEC-02
- **前置**：P04-T02。
- **结果**：只接受 PDF、DOCX、TXT、`.md/.markdown`，大小上限默认 25 MiB，伪造格式和明显二进制文本被拒绝。
- **允许文件**：`document_processing/validators.py`、错误码、fixtures、测试。
- **实现**：扩展名白名单；PDF `%PDF-`；DOCX 为合法 ZIP 且包含必要成员并限制压缩条目/展开大小；TXT/MD 可解码且无明显 NUL；0 字节拒绝；服务端 MIME 只作辅助。
- **验证**：四种合法 fixture；0 字节、超限、扩展名伪造、损坏 ZIP、二进制 TXT、路径名攻击。
- **负向**：仅修改扩展名不能通过；错误响应不回显服务器路径。
- **完成门**：400/413/415/422 语义与契约一致。

## P04-T04：实现流式上传、哈希去重和入库 API

- **需求**：DOC-02、DOC-04、DOC-05、LOG-01
- **前置**：P04-T01 至 T03。
- **结果**：`POST /knowledge-bases/{kb_id}/documents` 返回 202 与 `pending` 文档；同库相同内容返回 409 和已有文档 ID。
- **允许文件**：document repository/service、upload route/schema、日志、测试。
- **实现**：上传期间计算 size/hash；先写 `.part`，校验后原子完成；DB 失败补偿删除文件；不同知识库允许相同内容；日志含 kb_id/document_id/size/hash 前缀但不含全文。P04 尚无完整 pipeline，暂不注册 no-op BackgroundTask；文档保持 pending，P07-T03 必须在同一路由接入真实任务调度。
- **验证**：四格式上传 API、同名不同内容、同内容不同名、跨库重复、未知 KB、并发冲突测试。
- **负向**：请求中断或 DB commit 失败后无 `.part`/孤儿文件。
- **完成门**：响应不等待解析，且绝不直接返回 ready。

## P04-T05：实现文档列表、详情和上传阶段删除

- **需求**：DOC-02、DOC-12、KB-02
- **前置**：P04-T04。
- **结果**：列表/详情显示状态与错误摘要；删除 pending/failed 文档会清除文件和 SQL 记录。
- **允许文件**：document repository/service/routes/schemas、Dashboard 聚合、测试。
- **实现**：列表分页与状态筛选；GET 详情；DELETE 204；processing 文档当前返回 409；P07 扩展 ready 文档的 Chunk/向量清理。
- **验证**：列表/详情/404/删除；文件存在性；Dashboard 文档数定义为所有未删除文档。
- **负向**：跨知识库 ID 不得访问；清理失败返回可诊断错误且不谎报 204。
- **完成门**：P07 扩展点是明确 service，不在 route 内散落删除逻辑。

## P04-T06：执行上传生命周期 Gate

- **需求**：DOC-01 至 DOC-05、SEC-02、TEST-01
- **前置**：P04-T01 至 T05。
- **结果**：四类文件安全进入 pending；所有负向输入可预测；没有解析假结果。
- **验证**：从空库迁移；P01–P04 pytest/Ruff；真实 API 上传；核对磁盘文件、SQL hash/status；`git diff --check`。
- **负向**：重复、空、超限、伪格式、损坏 DOCX、恶意文件名、未知 KB。
- **完成门**：检查临时目录无 `.part` 残留，证据入状态表。
