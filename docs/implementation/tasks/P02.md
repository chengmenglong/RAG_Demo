# P02：配置、数据库与迁移基础

阶段目标：建立所有业务模块共用的配置、日志、错误、数据库和测试基础。

## P02-T01：实现分层环境配置

- **需求**：CFG-01、CFG-02、SET-03
- **前置**：P01 Gate。
- **结果**：开发默认 Demo 可启动；路径、数据库、Provider、超时、上传和只读 RAG 上下文预算都可由环境变量覆盖。
- **允许文件**：`backend/app/config/settings.py`、测试、根 `.env.example` 初版。
- **实现**：Pydantic Settings；路径解析以项目/data 根为基准；不读取或输出完整 Settings repr；数值边界校验；`RAG_MAX_CONTEXT_CHARS` 为环境只读且默认 12000，不进入 Settings API。
- **验证**：默认、环境覆盖、非法 chunk overlap、非法 provider、非法 URL/timeout 测试。
- **负向**：用测试密钥实例化配置，断言序列化和日志文本不含测试密钥。
- **完成门**：变量名与契约一致，默认值足以进入 Demo 模式。

## P02-T02：实现 request ID、结构化日志和统一错误

- **需求**：LOG-01、SEC-01、SET-02
- **前置**：P02-T01。
- **结果**：请求日志可关联；已知应用错误使用冻结 envelope；未知异常不向客户端返回栈。
- **允许文件**：`backend/app/core/errors.py`、`backend/app/config/logging.py`、`backend/app/core/middleware.py`、`main.py`、测试。
- **实现**：JSON 日志至少含 event/level/timestamp/request_id/path/status/duration；敏感字段脱敏；`X-Request-ID` 响应头。
- **验证**：health 日志结构测试、请求 ID 传入/生成测试、422/500 envelope 测试。
- **负向**：包含 `Authorization` 和测试 Key 的异常不得出现在捕获日志或响应。
- **完成门**：不使用 `except Exception: return success`，日志不记录正文全文。

## P02-T03：实现 SQLAlchemy engine、session 与 SQLite 安全参数

- **需求**：DB-01、ARC-01
- **前置**：P02-T01。
- **结果**：SQLite 默认数据库可持久化，session 生命周期可注入测试，数据库 URL 可替换 PostgreSQL。
- **允许文件**：`backend/app/db/base.py`、`session.py`、`api/deps.py`、测试。
- **实现**：SQLAlchemy 2；SQLite foreign_keys=ON、WAL、busy_timeout、`check_same_thread=False`；UTC helper；事务异常回滚。
- **验证**：临时文件库连接、外键 pragma、session rollback、URL 构造测试。
- **负向**：违反外键必须失败；rollback 后 session 可继续使用或被正确关闭。
- **完成门**：无散落 `create_engine`，请求依赖必定关闭 session。

## P02-T04：建立 Alembic 迁移框架

- **需求**：DB-01、DOCKER-01
- **前置**：P02-T03。
- **结果**：从仓库根目录可对空 SQLite 数据库执行 `upgrade head`，重复执行不报错。
- **允许文件**：`backend/alembic.ini`、`backend/alembic/**`、迁移测试。
- **实现**：`script_location` 不依赖当前 cwd；数据库 URL 从 Settings 注入；先建立可验证 baseline，后续表由独立 revision 添加。
- **验证**：对临时空库连续两次 `alembic upgrade head`；`alembic current`；迁移测试。
- **负向**：错误数据库路径返回非零，不得静默创建到意外 cwd。
- **完成门**：迁移不调用 `create_all` 代替生产迁移。

## P02-T05：建立后端测试数据库与依赖覆盖

- **需求**：TEST-01、TEST-02
- **前置**：P02-T03、P02-T04。
- **结果**：每个集成测试拥有隔离数据库/数据目录，能覆盖 FastAPI DB 和 Settings 依赖。
- **允许文件**：`backend/tests/conftest.py`、测试 helper、必要测试配置。
- **实现**：临时目录；明确 fixture scope；测试退出后关闭连接；不得触碰真实 `data/`。
- **验证**：写入/回滚隔离测试；连续运行同一测试两次；检查仓库 `data/` 未出现测试产物。
- **负向**：故意在测试中抛错后，下一个测试仍从干净状态开始。
- **完成门**：无全局共享可变 session，无测试顺序依赖。

## P02-T06：执行配置与数据库阶段 Gate

- **需求**：DB-01、CFG-01、LOG-01、SEC-01
- **前置**：P02-T01 至 T05。
- **结果**：全新数据库可迁移，应用可启动，错误与日志契约稳定。
- **验证**：在临时 DATA_DIR 下 `alembic upgrade head` 两次；运行 P01/P02 全测试与 Ruff；health/404/422 smoke；`git diff --check`。
- **负向**：无效数据库 URL 启动失败且错误不含 Key；全新目录之外无文件写入。
- **完成门**：所有证据记入状态表；失败则新增 P02 修复卡。
