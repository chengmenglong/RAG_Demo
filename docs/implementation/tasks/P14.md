# P14：综合验收

阶段目标：在不新增功能的前提下，从全新环境复核安装、迁移、测试、UI、核心业务、持久性和需求追踪。

## P14-T01：执行全新安装与空库迁移验收

- **需求**：FINAL-01、DB-01、README-01
- **前置**：P13 Gate。
- **结果**：新虚拟环境和清洁 Node 安装可按 README 成功；空 data 执行迁移两次；应用启动。
- **范围**：只改安装/迁移缺陷和 README；不得顺手新增功能。
- **验证**：重新创建 `.venv` 或隔离环境；pip editable install；`npm ci`；Alembic upgrade 两次/current；backend health；frontend build。
- **负向**：缺失必需变量时错误可读；默认 Demo 不要求 Key。
- **完成门**：记录实际版本、命令、退出码和耗时；缓存命中不作为唯一证据。

## P14-T02：执行后端全量质量验收

- **需求**：TEST-01、TEST-02、SEC-01、LOG-01
- **前置**：P14-T01。
- **结果**：后端 unit/integration、coverage、Ruff、迁移与 storage audit 全部通过。
- **验证**：`pytest backend/tests -q --cov=app --cov-report=term-missing`；Ruff；迁移；audit；核心 closed-loop 脚本。
- **负向**：单独运行测试模块、随机顺序或至少重复核心集成，排除顺序依赖。
- **完成门**：不得以“主要测试通过”忽略失败；所有失败要修复或 BLOCKED。

## P14-T03：执行前端全量质量与视觉验收

- **需求**：TEST-03、UI-01、UI-02、UI-03
- **前置**：P14-T01。
- **结果**：lint/typecheck/test/build 全绿；1440×900 和 1366×768 核心页无明显错位、溢出或 console error。
- **验证**：四条 npm 命令；Dashboard/KB/detail/Chat/Settings/404 截图；loading/empty/error/failed/timeout 状态。
- **负向**：后端断开、慢请求、长文件名、长回答、无页码 Citation。
- **完成门**：视觉问题有截图或明确观察，不只说“组件库看起来不错”。

## P14-T04：扩展并执行完整真实浏览器核心 E2E

- **需求**：GOV-02、TEST-04、CIT-02、DEMO-01
- **前置**：P14-T02、P14-T03。
- **结果**：Playwright 或等价真实浏览器完成建库→上传→ready→问答→引用→历史→删除。
- **允许文件**：扩展 P10 已建立的 `frontend/e2e/**` 与配置、发现缺陷的修复。
- **验证**：唯一事实断言 answer；source 文档名/页码或章节/excerpt；刷新历史；无关问题拒答；console/network 无未处理错误。
- **负向**：重复上传、failed reprocess、Provider timeout 至少各一条浏览器路径。
- **完成门**：保存 trace/screenshot 到被跟踪或明确忽略的验收目录，并在状态表记录路径。

## P14-T05：执行重处理、删除、重启和持久性验收

- **需求**：DOC-11、DOC-12、DOC-13、TEST-05、DOCKER-02
- **前置**：P14-T02。
- **结果**：reprocess 两次不累加；删除文档/KB 后当前存储清洁；重启后数据与历史可用；历史 Citation 快照仍显示。
- **验证**：记录前后 SQL/文件/vector counts；audit 0 orphan；backend restart；Docker down/up；源文档删除后的历史 source 状态。
- **负向**：处理中断后启动恢复；模拟清理部分失败后再次修复。
- **完成门**：每项有数值/对象 ID 证据，不以 UI 消失代替存储清理证明。

## P14-T06：执行真实 Provider 条件性 Smoke

- **需求**：PROV-01、PROV-02、FINAL-01
- **前置**：适配器合约测试通过；现场存在用户提供的 Key/服务才执行。
- **结果**：有条件时 OpenAI-compatible 和/或 Ollama 至少一次真实 embedding + chat + citation；没有条件时在证据字段准确写 `NOT_RUN` 或 `BLOCKED`，这不是任务状态。
- **范围**：不得自行购买、泄露或提交 Key；不得把 Demo 当 live。
- **验证**：只记录 provider、模型、时间、成功/错误分类和 request ID，不记录 Key/完整 prompt。
- **负向**：无 Key/Ollama 未运行时不反复尝试，不把连接失败写成产品缺陷。
- **完成门**：适配器合约必须 PASS；本任务可据此标 DONE，外部 live 的证据子状态可为 NOT_RUN/BLOCKED，但最终限制必须说明。

## P14-T07：完成需求追踪逐项补证

- **需求**：原始全部、FINAL-01
- **前置**：P14-T01 至 T06。
- **结果**：每个 Must 都能在静态追踪矩阵映射到任务，并在 `EXECUTION_STATE.md` 有代码位置 + 自动命令或手工/E2E 证据 + 状态。
- **范围**：只读审计追踪矩阵；更新状态表和缺陷修复，不向静态 `01_REQUIREMENTS_TRACEABILITY.md` 写动态状态。
- **验证**：搜索空 evidence、`TODO`、无主任务、伪 PASS；核对 README 声明与矩阵。
- **负向**：外部 live 与 Docker 若未运行必须显式 BLOCKED/NOT_RUN，不能留空。
- **完成门**：Gate A–H 均有证据；所有 Must PASS，或对应任务由用户明确批准为 SKIPPED。
