# P05：文本解析、清洗与 Chunk

阶段目标：用纯函数和明确数据类型，把四类文档转换为可溯源、可重复的 Chunk；尚不调用 Embedding。

## P05-T01：定义 Parser、SourceSegment 和注册表契约

- **需求**：ARC-02、DOC-06、DOC-07
- **前置**：P04 Gate。
- **结果**：所有解析器输出统一 segment：文本、用户页码、章节、序号和可诊断 metadata。
- **允许文件**：`document_processing/types.py`、`parsers/base.py` 或等价文件、registry、测试。
- **实现**：page_number 从一开始就是 1-based 或 null；parser 按扩展名选择；错误映射为稳定 code；不允许 parser 写数据库。
- **验证**：注册四格式、未知格式失败、segment schema 不变量测试。
- **负向**：页码 0、空文本 segment 和负序号不能进入后续处理。
- **完成门**：后续 chunk/citation 不需要猜页码来源。

## P05-T02：实现 TXT 与 Markdown 解析

- **需求**：DOC-01、DOC-07、DOC-08
- **前置**：P05-T01。
- **结果**：TXT 生成段落 segment；Markdown 保留标题层级为 section。
- **允许文件**：对应 parser、fixtures、测试。
- **实现**：优先 UTF-8-SIG，使用 charset-normalizer 有限回退；拒绝二进制；Markdown 不执行 HTML/脚本；标题归属后续段落。
- **验证**：中文/英文/BOM/不同换行、Markdown 多级标题、无标题、空白文件。
- **负向**：无法可靠解码和仅空白文件进入明确失败。
- **完成门**：section 稳定，page_number 为 null。

## P05-T03：实现 PDF 与 DOCX 解析

- **需求**：DOC-01、DOC-07、SEC-02
- **前置**：P05-T01。
- **结果**：PDF 每页保留实际页码；DOCX 保留 Heading section、段落和必要表格文本。
- **允许文件**：对应 parser、真实小 fixture、测试。
- **实现**：pypdf 按页；加密/损坏/无文本 PDF 明确失败并提示 OCR 未包含；python-docx 限制异常容器；DOCX 无可靠页码返回 null。
- **验证**：至少两页 PDF 检查页码和独特文本；带标题/表格 DOCX；中文文本。
- **负向**：扫描/空 PDF、加密 PDF、损坏 DOCX 不产生 chunk。
- **完成门**：不跨页拼成无法定位的 segment。

## P05-T04：实现保来源的文本清洗器

- **需求**：DOC-08
- **前置**：P05-T02、P05-T03。
- **结果**：统一换行、空白和不可见控制符，同时保持 segment 的页码/章节归属。
- **允许文件**：`document_processing/cleaner.py`、测试。
- **实现**：不对内容做 LLM 改写；保留段落边界；过滤空 segment；记录字符数。
- **验证**：CRLF、连续空白、Unicode 空格、控制字符、中文标点测试。
- **负向**：清洗后为空时抛 `NO_EXTRACTABLE_TEXT`，不得成功返回空列表。
- **完成门**：清洗是确定性的，同输入两次完全一致。

## P05-T05：实现可配置、段落优先的字符 Chunker

- **需求**：DOC-09、SET-03
- **前置**：P05-T04。
- **结果**：每个 chunk 不超过 `chunk_size`，相邻 chunk 按字符 overlap，保留页码/章节且 PDF 不跨页。
- **允许文件**：`document_processing/chunker.py`、类型、测试。
- **实现**：默认 1000/150 字符；分隔优先级为空段、换行、句末、空格、硬切；稳定 ordinal；`0 <= overlap < size`。
- **验证**：短文、超长段落、多页、中文无空格、零 overlap、接近边界、顺序/重叠断言。
- **负向**：size 太小/过大、overlap 相等或更大、空输入必须拒绝。
- **完成门**：无空 chunk，不丢非空文本，元数据与来源一致。

## P05-T06：实现 Chunk 模型、迁移和 Repository

- **需求**：DB-02、DOC-07、DOC-10
- **前置**：P05-T05。
- **结果**：Chunk 模型可持久化 document/kb、ordinal、content、page/section、vector_id、profile、字符位置和时间；纯解析阶段只生成 Chunk Draft。
- **允许文件**：`models/chunk.py`、repository/schema、关系、一个迁移、测试。
- **实现**：同 document ordinal 唯一；kb_id 冗余用于隔离并有索引；不得把无 vector_id/profile hash 的 Draft 写入业务库；Repository 测试使用已绑定的合成 KB、profile hash 和稳定 vector UUID，P07 才由正式 pipeline 写入。
- **验证**：迁移、级联、唯一约束、分页/计数、Dashboard chunk 聚合补测。
- **负向**：Chunk 的 KB 与 Document KB 不一致必须由 service 拒绝。
- **完成门**：字段足以构造 Citation，无 embedding 大数组存 SQL。

## P05-T07：组合解析、清洗、Chunk 纯处理服务并执行 Gate

- **需求**：DOC-06 至 DOC-09、TEST-01
- **前置**：P05-T01 至 T06。
- **结果**：给定四类 fixture，服务返回可持久化 chunk drafts，尚不改变文档状态或调用 Provider。
- **允许文件**：`document_processing/service.py` 或 pipeline 的纯处理部分、测试。
- **验证**：四类 end-to-end parsing unit test；页码/章节/ordinal；空文本失败；P01–P05 全测试/Ruff；`git diff --check`。
- **负向**：任一 parser 异常必须带 document context 传播，不返回部分成功。
- **完成门**：fixture 和测试小而真实，未通过不得进入 Provider 阶段。
