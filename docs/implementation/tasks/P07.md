# P07：向量写入与检索

阶段目标：把正式文档流水线接到 Chroma，并保证知识库隔离、幂等、补偿清理和可配置检索。

## P07-T01：实现 VectorStore 协议与 Chroma PersistentClient Adapter

- **需求**：ARC-02、DOC-10、STORE-01
- **前置**：P06 Gate。
- **结果**：调用方可 upsert/search/delete document/delete KB/health，不接触 Chroma 原始响应。
- **允许文件**：`vectorstores/base.py`、`vectorstores/chroma.py`、测试。
- **实现**：预计算 embedding；collection 按 profile hash 命名；cosine；metadata 含 knowledge_base_id、document_id、chunk_id、profile_hash，以及有值时的 page_number/section；distance 归一为越大越相似的 score；持久路径配置；进程内可重入锁串行化 upsert/delete/collection mutation，单 worker 限制仍保留。
- **验证**：临时持久目录 upsert/search/delete/reopen；跨 KB filter；top-k；score 排序。
- **负向**：维度错误、缺 collection、损坏路径返回稳定错误；测试不写真实 data。
- **完成门**：业务层无 Chroma-specific distance 或 where 语法。

## P07-T02：实现批量 Embedding 与索引服务

- **需求**：DOC-10、PROV-01、LOG-01
- **前置**：P07-T01。
- **结果**：chunk drafts 按配置批量 embedding，固定 UUID vector_id，并构造可补偿的 SQL/向量记录。
- **允许文件**：`services/indexing_service.py`、schema/type、测试。
- **实现**：第一次成功索引用 compare-and-set 锁 profile：`profile_hash IS NULL` 的条件更新只有一个任务获胜，失败者 reload 后必须比较完整 profile；批次顺序/维度校验；日志只含数量/时长；point ID 与 chunk ID 一致或稳定映射。
- **验证**：多批次、最后小批、维度不一、Provider 中途失败、profile mismatch。
- **负向**：任一批失败不得返回“部分成功”；NaN/空向量不写 Chroma。
- **完成门**：调用两次相同输入不会新增重复 vector ID。

## P07-T03：实现完整 Document Processing Pipeline

- **需求**：DOC-06、DOC-10、DOC-11、LOG-01
- **前置**：P05-T07、P07-T02。
- **结果**：BackgroundTask 仅凭 document_id 完成 extracting→cleaning→chunking→embedding→indexing→ready。
- **允许文件**：`document_processing/pipeline.py`、document/index services、路由调度、测试。
- **实现**：任务自建 session；P04 上传路由在本卡接入真实 BackgroundTask 调度，不保留 no-op；逐阶段提交可观察状态；处理数据先在内存/临时结构，向量成功后 SQL commit；DB 失败补偿删本次向量；任何失败状态为 failed 且无可检索半成品。
- **验证**：TXT 到 ready 集成；逐阶段注入失败；状态、错误 code、chunk_count、SQL/Chroma 数一致。
- **负向**：请求 session 关闭后任务仍能运行；异常不得被 BackgroundTask 静默吞掉。
- **完成门**：ready 只在 SQL 和向量均完成后出现。

## P07-T04：实现启动恢复和孤立索引补偿

- **需求**：DOC-11、DOC-13、SEC-01
- **前置**：P07-T03。
- **结果**：进程重启后遗留 pending/processing 文档变为可理解的 failed，可人工重新处理；按 document_id 清除可能半成品。
- **允许文件**：startup recovery service、main lifespan、测试。
- **实现**：启动扫描 pending 和 processing；清理 SQL chunks/Chroma vectors 后置为 `failed/failed + PROCESS_INTERRUPTED`；补偿清理失败仍保持合法 failed 状态并记录 cleanup 错误；不得发明 blocked 文档状态或自动无限重试。
- **验证**：预置 processing + 半向量后模拟启动；检查 failed、清理和日志；重复启动幂等。
- **负向**：恢复清理失败必须保留合法 failed 状态、cleanup error 和日志，不能把文档标 ready 或发明 blocked 文档状态。
- **完成门**：明确记录 BackgroundTasks 不是持久任务队列的限制。

## P07-T05：完善文档 reprocess、delete 与 chunks 查询

- **需求**：DOC-02、DOC-11、DOC-12、KB-03
- **前置**：P07-T03。
- **结果**：`POST /documents/{id}/reprocess` 清理旧当前索引后重新排队；delete 清理文件、SQL chunks、Chroma vectors 和 Document；知识库删除调用同一清理服务；`GET /documents/{id}/chunks` 分页返回 ready 文档的原始 Chunk。
- **允许文件**：document/knowledge base services、routes、测试。
- **实现**：processing 时 reprocess/delete 均返回 409；KB 有 pending/processing 文档时整体删除返回 409；reprocess 保持 document_id 和原文件；删除 pending 后已排队任务按 ID 查询不到时安全退出；每次失败不保留旧检索数据；历史 citation 快照到 P08；chunks 响应不含绝对路径且只返回 ready 正式记录；清理顺序/补偿有日志。UI 可写“Retry”，但不得新增 `/retry` 端点。
- **验证**：处理两次 chunk/vector 数不累加；删除后各存储均无结果；删除 KB 多文档；重复删除 404/幂等内部清理。
- **负向**：模拟文件或 Chroma 删除失败，API 不谎报完成，并可再次清理。
- **完成门**：Dashboard 计数和存储实际一致。

## P07-T06：实现知识库隔离的 Retriever

- **需求**：RAG-01、RAG-02、RAG-05
- **前置**：P07-T01、P07-T03。
- **结果**：查询使用知识库锁定 profile，候选按 score 降序，阈值后最多返回 top_k 个 READY chunk。
- **允许文件**：`rag/retriever.py`、类型、测试。
- **实现**：先取 `min(top_k*3, 60)` 候选；验证 SQL chunk 和 ready document；统一 score 范围/方向；最大上下文预算在 P08 最终截取。
- **验证**：已知唯一事实排序、threshold 边界、top-k、跨库隔离、被删/failed 文档过滤、重开 Chroma 后检索。
- **负向**：空库、空问题、profile 不可用返回明确结果/错误，不调用 LLM。
- **完成门**：score 语义只有 adapter 定义，业务不反转 distance。

## P07-T07：执行向量、处理与检索 Gate

- **需求**：DOC-06、DOC-10 至 DOC-13、RAG-01、RAG-02、TEST-05
- **前置**：P07-T01 至 T06。
- **结果**：四格式文档均可到 ready，重启后仍能检索，重试/删除无孤儿。
- **验证**：P01–P07 全 pytest/Ruff；四 fixture 正式 pipeline；跨库检索；重启 PersistentClient；reprocess 两次；delete；扩展 health 返回 database/vector_store/demo_mode 且依赖故障时 503/degraded；`git diff --check`。
- **负向**：embedding/index/DB commit 失败、僵尸 processing、低阈值/高阈值。
- **完成门**：SQL、文件、Chroma 审计数量一致；失败则创建 P07 修复卡。
