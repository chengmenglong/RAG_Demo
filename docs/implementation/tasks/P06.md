# P06：Settings 与 Provider

阶段目标：实现非敏感运行设置和可替换 Provider；无外部服务时确定性 Demo 可用。

## P06-T01：实现非敏感 Settings 持久化和 API

- **需求**：SET-01、SET-02、SET-03、CFG-02
- **前置**：P05 Gate。
- **结果**：`GET/PATCH /settings` 可读取/部分修改非敏感参数，刷新后持久；响应只含 `*_api_key_configured` 布尔值。
- **允许文件**：settings model/migration/repository/service/schema/route、测试。
- **实现**：单例行字段可空；不把环境值复制进数据库，DB 非 null 值覆盖环境/内置默认；PATCH 显式 null 清除覆盖；Key 永远只来自环境；LLM/temp/top-k/threshold 立即生效，chunk 只影响重处理/新文档。
- **验证**：初始化、更新、重启持久、边界校验、并发更新策略测试。
- **负向**：在环境放测试 Key，断言响应、数据库、日志、异常都不含该值。
- **完成门**：Embedding 设置变更不能静默改变已锁定知识库 profile。

## P06-T02：定义 Provider 协议、类型和错误边界

- **需求**：PROV-01、PROV-02、PROV-03、ARC-02
- **前置**：P06-T01。
- **结果**：Embedding/LLM 调用方只依赖内部协议和普通数据类型，不依赖厂商 SDK 对象。
- **允许文件**：`providers/base.py`、`types.py`、`errors.py`、测试。
- **实现**：`embed_documents`、`embed_query`、`profile`、`chat`；profile 含 provider、去凭据后的规范化 base URL、model、实际 dimension、normalization、profile_version 和 hash；统一 timeout/auth/rate-limit/upstream/config 错误。
- **验证**：协议假实现合约测试、维度不一致、空向量、NaN/Inf、空答案测试。
- **负向**：错误字符串不得包含 request header、Key 或完整 Prompt。
- **完成门**：Provider 可被 factory 注入，业务层不写 provider if/else 链。

## P06-T03：实现确定性 Demo Embedding 与 Demo LLM

- **需求**：DEMO-01、TEST-02、RAG-04
- **前置**：P06-T02。
- **结果**：无网络/Key 可为中英文文本生成稳定向量，并从真实命中片段构造明确标识的演示回答。
- **允许文件**：`providers/demo.py`、测试。
- **实现**：BLAKE2b/等价稳定字符与词 n-gram hashing，固定 384 维，L2 归一化；禁止 Python `hash()`；Demo LLM 只使用传入 source，输出 `[S1]` 等合法标签。
- **验证**：跨两个独立 Python 进程同输入向量字节/近似值一致；相近关键字得分高于无关文本；无 source 固定拒答。
- **负向**：不得从固定问题字典直接返回答案；UI/API 可识别 `demo_mode=true`。
- **完成门**：Demo 是关键词型检索，文档明确不冒充真实语义能力。

## P06-T04：实现 OpenAI-compatible Provider

- **需求**：PROV-01、PROV-02、PROV-03
- **前置**：P06-T02。
- **结果**：同一 adapter 支持可配置 Base URL、模型、Key 的 embedding 与非流式 chat。
- **允许文件**：`providers/openai_compatible.py`、factory 相关测试；不得做 live 调用。
- **实现**：官方 SDK；显式 timeout 和有限 retry；批量 embeddings；响应维度/顺序检查；客户端可关闭或有明确生命周期。
- **验证**：Mock SDK/transport 断言 URL、model、inputs、temperature；auth/429/5xx/timeout 映射；Key 不出日志。
- **负向**：缺 Key 或 model 时在调用前返回配置错误；4xx 不无限重试。
- **完成门**：仅报告适配器/Mock 合约通过，不能报告真实服务已验证。

## P06-T05：实现 Ollama Provider

- **需求**：PROV-01、PROV-02、PROV-03
- **前置**：P06-T02。
- **结果**：通过 Ollama `/api/embed` 和 `/api/chat` 支持本地 Embedding/LLM。
- **允许文件**：`providers/ollama.py`、HTTP mock 测试。
- **实现**：httpx；Base URL 标准化；批量 input；非流式 chat；timeout；响应 schema/维度校验；本机与 Docker URL 由环境配置。
- **验证**：respx/mock transport 检查请求和响应；连接拒绝、timeout、非 JSON、模型不存在错误。
- **负向**：Ollama 未运行时不得回退伪装成成功；可以明确建议 Demo。
- **完成门**：live smoke 是可选现场证据，与 Mock 测试分列。

## P06-T06：实现 Provider Factory 与 Profile 锁定规则

- **需求**：ARC-02、DOC-10、SET-03
- **前置**：P06-T03 至 T05。
- **结果**：服务根据当前设置构造正确 Provider；知识库首次索引后记录并使用唯一 Embedding Profile。
- **允许文件**：`providers/factory.py`、knowledge base service/schema、测试。
- **实现**：显式 provider registry；非法名称稳定错误；未绑定 KB 首次索引使用当前有效设置并在取得首批实际维度后绑定完整 profile；已绑定 KB 的上传、查询和 reprocess 都从 KB profile 快照构造 Provider。不同 profile 返回 `EMBEDDING_PROFILE_MISMATCH`，改模型只能新建 KB 并重新上传，MVP 不提供 profile 迁移。
- **验证**：三 provider 选择、缺配置、profile 相同/不同、dimension 检查。
- **负向**：不得因全局 Settings 改变而查询旧库时临时采用新 embedding。
- **完成门**：profile hash 算法稳定，包含规范化且已去除凭据/敏感 query 的 Base URL，但绝不包含 API Key。

## P06-T07：执行 Settings 与 Provider Gate

- **需求**：SET-01 至 SET-03、PROV-01 至 PROV-03、DEMO-01
- **前置**：P06-T01 至 T06。
- **结果**：无 Key 环境默认 Demo；设置安全；适配器合约和失败映射通过。
- **验证**：P01–P06 全 pytest/Ruff；Demo 跨进程稳定性；Settings Key 泄露扫描；OpenAI/Ollama Mock 合约；`git diff --check`。
- **负向**：非法 provider、timeout、Key 缺失、profile mismatch。
- **完成门**：外部 live 未执行时准确标 `NOT_RUN`，不阻塞下一阶段 Demo 实现。
