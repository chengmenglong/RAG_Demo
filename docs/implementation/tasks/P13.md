# P13：Demo、Docker 与 README

阶段目标：让全新环境可按文档启动、无 Key 演示，并用容器验证部署拓扑。当前基线未发现 Docker CLI，执行时必须重新检查。

## P13-T01：提供中立 Demo 数据与幂等 seed/reset

- **需求**：DEMO-01、DEMO-02、README-01
- **前置**：P12 Gate。
- **结果**：`demo_data/` 含至少 Markdown、TXT 和可选 PDF/DOCX 样本；seed 调用正式 service/pipeline 创建一个中立知识库，执行两次不重复。
- **允许文件**：`demo_data/**`、`backend/app/scripts/seed_demo.py`、安全 reset 脚本、测试。
- **实现**：样本含可验证唯一事实；无客户名/Logo/机密；seed 按稳定标识+hash 幂等；默认生产启动不自动 seed；reset 只删 Demo 标记资源。
- **验证**：空库 seed→ready→提问→Citation；再 seed 计数不变；reset 不删除普通用户库。
- **负向**：Demo Provider/数据明确标识，不冒充真实客户和真实模型。
- **完成门**：seed 不直接伪造 Chunk/向量，必须走正式 upload/process service。

## P13-T02：创建后端生产 Dockerfile

- **需求**：DOCKER-01、DOCKER-02、SEC-01
- **前置**：P13-T01。
- **结果**：后端镜像可安装锁定依赖、运行 Alembic、以非 root 用户单 worker 启动 Uvicorn。
- **允许文件**：`backend/Dockerfile`、必要 entrypoint、`.dockerignore`、依赖锁定文件。
- **实现**：Python 3.12 slim 基线；分层缓存；健康检查 endpoint；data 目录可写；Key 只运行时注入；shell 文件 LF。
- **验证**：Docker 可用时 build 与容器 health；不可用时先做 Dockerfile 静态 review 并标 `BLOCKED`，不能写 PASS。
- **负向**：镜像上下文不含 `.env`、data、uploads、Chroma、tests cache、Git。
- **完成门**：命令与实际模块路径一致，不使用多 worker 写 embedded Chroma。

## P13-T03：创建前端多阶段 Dockerfile 与 Nginx 代理

- **需求**：DOCKER-01、UI-01
- **前置**：P12 Gate。
- **结果**：前端 production bundle 由 Nginx 提供，SPA fallback 正常，`/api/` 反代 backend，上传大小匹配后端限制。
- **允许文件**：`frontend/Dockerfile`、`frontend/nginx.conf`、docker ignore、测试/检查脚本。
- **实现**：npm ci 构建；非 root/最小 Nginx 能力；静态缓存；`try_files`；代理 headers/request ID；客户端不使用容器内 hostname。
- **验证**：本地 build；Docker 可用时访问 `/` 深链和 `/api/v1/health`；上传限制 smoke。
- **负向**：刷新 `/knowledge-bases/{id}` 不得 404；API 失败不得回落 index.html 伪 200。
- **完成门**：bundle 无 Key 和 localhost 硬编码。

## P13-T04：创建 Compose、持久卷和完整 `.env.example`

- **需求**：DOCKER-01、DOCKER-02、CFG-01、STORE-01
- **前置**：P13-T02、P13-T03。
- **结果**：`docker compose up --build` 启动 backend/frontend，named volume 持久化 SQLite、uploads、Chroma；前端端口 3000。
- **允许文件**：根 `docker-compose.yml`、`.env.example`、必要 health/启动脚本。
- **实现**：depends_on health；backend `workers=1`；迁移先执行；Demo 默认无 Key可用；Ollama 宿主说明 `host.docker.internal`；不在 compose 写真实 Key。
- **验证**：`docker compose config`、build/up/ps/logs；health、页面、core smoke；down/up 后数据仍在。
- **负向**：普通 `docker compose down` 不丢 volume；仅明确 reset 命令才删除 Demo/volume，文档警告不可恢复。
- **完成门**：当前无 Docker 时任务状态为 BLOCKED，解除条件是可用 Docker Desktop/Linux engine。
