# P11：文档管理前端

阶段目标：让用户在浏览器中清楚区分上传进度和后台处理状态，并能处理失败、reprocess 和 delete。

## P11-T01：实现文档 API hooks、状态表与筛选

- **需求**：DOC-02、DOC-05、UI-02
- **前置**：P10 Gate。
- **结果**：知识库详情列出文档名、类型、大小、状态、阶段、Chunk 数、创建/更新时间和可读错误。
- **允许文件**：document types/services/hooks/components/tests。
- **实现**：状态 Tag 统一；分页/状态筛选；error code 映射；保留 request ID；不在前端推断 ready。
- **验证**：MSW 覆盖 pending/processing/ready/failed/empty/error。
- **负向**：未知状态显示安全 fallback，不白屏。
- **完成门**：状态文案与后端状态机一一对应。

## P11-T02：实现拖拽上传与字节进度

- **需求**：DOC-01、DOC-02、UI-02
- **前置**：P11-T01。
- **结果**：用户可拖拽/选择四格式，看到 0–100% 网络上传进度；服务端接受后切换为后台处理状态。
- **允许文件**：UploadDropzone、upload service/hook、tests。
- **实现**：react-dropzone 或 Ant Upload；客户端只作早期格式/大小提示，服务端仍权威；一次批量可逐文件结果；禁重复提交。
- **验证**：选择/拖拽、progress event、成功 202、413/415/409、部分文件失败。
- **负向**：409 显示已有文档信息；前端改扩展不能绕过后端。
- **完成门**：上传到 100% 不显示“解析完成”。

## P11-T03：实现 processing 轮询与终态反馈

- **需求**：DOC-02、DOC-05、DOC-06
- **前置**：P11-T01、P11-T02。
- **结果**：存在 pending/processing 时定期刷新，全部终态后停止；阶段和失败原因更新及时。
- **允许文件**：document polling hook/table components/tests。
- **实现**：约 2 秒间隔、页面不可见可降频；组件卸载取消；失败 Toast 只提示一次；手动刷新。
- **验证**：fake timers 状态序列、停止条件、卸载、network error 恢复。
- **负向**：不得无限快速请求或每次轮询弹 Toast。
- **完成门**：刷新页面后继续依据后端状态，不依赖内存进度。

## P11-T04：实现 reprocess、delete 和确认反馈

- **需求**：DOC-02、DOC-12、UI-02
- **前置**：P11-T03。
- **结果**：failed/ready 文档可 reprocess；非 processing 文档可确认删除；操作后统计和列表一致。
- **允许文件**：document actions/hooks/tests。
- **实现**：按状态启停按钮；mutation loading；409 可读；删除警告会清除源文件与当前索引但历史引用快照保留；ready 文档 reprocess 前必须明确警告“现有索引会被替换，失败后需再次处理”，并支持取消不发请求。UI 可写“Retry”，后端仍只调用 `/reprocess`。
- **验证**：reprocess confirm/cancel→pending→ready、delete cancel/confirm/success/failure、缓存更新。
- **负向**：processing 时按钮禁用且后端 409 仍被正确处理。
- **完成门**：失败操作不先从 UI 乐观永久移除数据。

## P11-T05：实现文档详情与 Chunk 来源浏览

- **需求**：DOC-07、CIT-02 的基础
- **前置**：P11-T01。
- **结果**：可查看文档元数据、错误、处理配置和分页 Chunk 摘要，页码/章节为空时准确显示。
- **允许文件**：前端 Drawer/page、hooks 和 tests；复用 P07 已冻结的只读 chunks API，不在前端阶段新增后端端点。
- **实现**：只展示当前文档的 chunk；长文本折叠；不开放服务器路径；本功能为调试/溯源基础。
- **验证**：PDF page 1-based、Markdown section、无页码、空 chunks、404。
- **负向**：跨 KB/document 访问被拒绝；UI 不渲染 raw HTML。
- **完成门**：内容与数据库 chunk 完全一致，不二次摘要。

## P11-T06：执行文档 UI Gate

- **需求**：DOC-01、DOC-02、DOC-05、DOC-12、TEST-04
- **前置**：P11-T01 至 T05。
- **结果**：真实浏览器可上传四格式中的代表文件，观察到 ready/failed，reprocess/delete 正确。
- **实现**：为 P11 核心流程增加带 `@p11` 标签的 Playwright 用例。
- **验证**：frontend 全质量命令；`npm --prefix frontend run test:e2e -- --grep "@p11"`；浏览器拖拽真实 fixture；network progress；轮询；失败 reprocess；delete；console/network；`git diff --check`。
- **负向**：空/伪格式/超限/重复；后端处理中断。
- **完成门**：Dashboard/KB 统计同步；截图和操作证据入状态表。
