# P09：后端安全、稳定性与日志

阶段目标：在接前端前系统化清理安全、异常、资源和跨存储一致性问题。

## P09-T01：补齐 API 参数与统一错误矩阵

- **需求**：SEC-01、DOC-03、PROV-03
- **前置**：P08 Gate。
- **结果**：400/404/409/413/415/422/502/503/504 均有稳定 code、message、details、request_id，生产响应无栈。
- **允许文件**：core errors/handlers、schemas/routes、参数化测试。
- **实现**：按 `03_API_DATA_CONTRACTS.md` 映射；Pydantic validation 转换为统一 envelope；details 不泄露内部路径/SQL。
- **验证**：错误矩阵参数化 API 测试；OpenAPI 关键响应说明。
- **负向**：未知异常只在服务端记录诊断，客户端返回通用 500。
- **完成门**：不得用 200 包裹失败，也不得所有失败都返回 500。

## P09-T02：审计 Provider timeout、retry 与客户端生命周期

- **需求**：PROV-03、SEC-01
- **前置**：P06 Provider、P08 RAG。
- **结果**：可重试错误有限退避；不可重试 4xx 立即失败；HTTP/SDK 客户端可关闭，无每次调用泄漏连接。
- **允许文件**：providers、factory/lifespan、测试。
- **实现**：明确最大重试次数；配置缺失为 503 `PROVIDER_NOT_CONFIGURED`，连接拒绝/限流/上游 5xx 为 502 `PROVIDER_ERROR`，认证为 502 `PROVIDER_AUTH_FAILED`，超时为 504 `PROVIDER_TIMEOUT`；关闭钩子；日志不含 headers/body。
- **验证**：Mock 断言 retry 次数和退避接口；auth 不重试；timeout；应用 shutdown 调用 close。
- **负向**：重试不能导致重复保存 Chat message 或重复索引。
- **完成门**：资源所有权清晰，异常链保留但对外脱敏。

## P09-T03：实现日志脱敏与流程事件覆盖

- **需求**：LOG-01、SET-02
- **前置**：P09-T01。
- **结果**：upload、parse、embedding、vector write、RAG、LLM、cleanup、exception 都有结构化开始/结束/失败事件。
- **允许文件**：logging helpers、中间件、各 service 的事件调用、测试。
- **实现**：request/document/kb/session ID、duration、counts、status；集中 redaction Key 名和 Authorization；正文只记录长度/哈希前缀。
- **验证**：捕获完整核心闭环日志，断言事件齐全和可关联；注入测试 secret 全文搜索不得出现。
- **负向**：文件系统绝对路径、完整 Prompt、完整 Chunk、API 响应 body 不进入普通日志。
- **完成门**：异常仍可诊断，脱敏不是删除所有上下文。

## P09-T04：实现跨存储一致性审计与安全清理命令

- **需求**：DOC-11、DOC-12、KB-03、STORE-01
- **前置**：P07-T05。
- **结果**：只读 audit 可报告孤儿文件、SQL chunks、vectors、缺失文件和计数差异；修复模式必须显式启用且限定 data 根。
- **允许文件**：`backend/app/scripts/audit_storage.py`、service/helper、测试。
- **实现**：默认只读；输出机器可读摘要；修复只处理能被 ID 精确归属的孤儿；不递归删除未知宽目录。
- **验证**：构造每类孤儿并 audit；dry-run 不改；fix 后只移除目标；正常库零问题。
- **负向**：data root 为 `/`、用户目录或解析失败时拒绝 fix。
- **完成门**：命令不能绕过 storage/vector adapter。

## P09-T05：补齐上传、路径、数据库和并发安全测试

- **需求**：SEC-01、SEC-02、DOC-03、DOC-11
- **前置**：P09-T01 至 T04。
- **结果**：关键攻击/故障输入有自动测试，重复请求不会破坏数据。
- **允许文件**：测试和为修复测试暴露问题所需后端文件。
- **实现/验证**：路径穿越、Unicode/保留名、伪扩展、ZIP bomb 限制、空/超大、SQL 失败 rollback、重复并发、BackgroundTask 失败、删除部分失败、CORS 允许列表。
- **负向**：测试不得通过 monkeypatch 掉被测安全逻辑；不得放宽断言只求绿。
- **完成门**：每类安全要求至少一个成功拒绝证据。

## P09-T06：执行后端硬化 Gate

- **需求**：SEC-01、SEC-02、LOG-01、TEST-01、REVIEW-01
- **前置**：P09-T01 至 T05。
- **结果**：后端完整测试、lint、迁移、核心闭环、审计命令全部通过。
- **验证**：空库 migration；`pytest -q --cov=app`；Ruff；核心闭环；storage audit；secret 文本扫描；`git diff --check`。
- **负向**：至少复跑 no-hit、timeout、恶意上传、retry/delete 失败和重启恢复。
- **完成门**：覆盖率数字只作证据，不得用高覆盖替代行为检查；重要缺陷创建修复卡。
