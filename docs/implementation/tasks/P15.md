# P15：独立 Code Review、修复与发布审查

阶段目标：先独立审查，再把重要问题转成修复卡，最后重跑 P14；不能以“已自测”替代 Review。

## P15-T01：审查架构、API、数据库和资源生命周期

- **需求**：REVIEW-01、ARC-01、DB-01、SEC-01
- **前置**：P14 Gate。
- **结果**：形成按 P0/P1/P2/P3 分级、带文件/行、影响、复现和建议的审查清单。
- **范围**：只读审查，记录 `FINAL_REVIEW.md`；此卡不边看边大重构。
- **检查**：分层依赖、重复、事务、N+1、迁移、级联、session/client 关闭、BackgroundTasks、错误码、并发。
- **验证**：逐项引用代码和测试；随机抽 API 与数据模型对照契约。
- **负向**：不能写“未发现问题”而不给审查范围和证据。
- **完成门**：P0/P1/P2/P3 分类，误报也要说明关闭理由。

## P15-T02：审查文档处理、RAG、Prompt、Citation 和安全

- **需求**：REVIEW-01、DOC-06、RAG-03、CIT-01、SEC-02
- **前置**：P15-T01；逻辑上独立但仍按单任务协议串行执行。
- **结果**：确认页码、profile、score、no-hit、引用白名单、补偿清理和 prompt injection 边界。
- **范围**：只读审查和 `FINAL_REVIEW.md`。
- **检查**：四 parser、chunk overlap、向量隔离、重处理、未知 label、历史快照、超时/重试、日志脱敏、路径/ZIP 风险。
- **验证**：至少手工追一条完整文档和一条失败路径，从磁盘到 UI source。
- **负向**：不得因 Demo 测试通过就断言真实 provider 质量正确。
- **完成门**：每个重要不变量有代码与测试位置。

## P15-T03：审查前端状态、类型、可访问性和 UX

- **需求**：REVIEW-01、UI-01 至 UI-03、CHAT-02
- **前置**：P14-T03。
- **结果**：识别缓存、轮询、重复提交、错误恢复、XSS、路由、键盘和视觉问题。
- **范围**：只读审查和 `FINAL_REVIEW.md`。
- **检查**：Query invalidation、组件卸载、loading/empty/error、Modal focus、citation keyboard、长内容、深链、console、bundle secrets。
- **验证**：两 viewport、键盘操作、慢网/断网、恶意 Markdown、刷新历史。
- **负向**：不能只审 CSS 或只看 happy path。
- **完成门**：每个发现带复现和用户影响。

## P15-T04：审查 Docker、配置、README、复用性和测试遗漏

- **需求**：REVIEW-01、DOCKER-01、README-01、ARC-02
- **前置**：P14-T01、P14-T07。
- **结果**：镜像、Compose、volume、proxy、env、启动文档、扩展点和测试声明一致。
- **范围**：只读审查和 `FINAL_REVIEW.md`。
- **检查**：secret/image context、workers、health、migration、SPA/API proxy、Ollama URL、README 命令、未实现功能误报、客户硬编码。
- **验证**：compose config/up 证据；仓库关键词扫描；追踪矩阵空缺审计。
- **负向**：Docker 不可用时必须保留阻塞，不能静态看完即关闭发现。
- **完成门**：可复用边界清晰，无固定客户、Logo、知识库或模型厂商。

## P15-T05：把重要发现拆成修复卡并完成修复

- **需求**：REVIEW-01
- **前置**：P15-T01 至 T04。
- **结果**：每个 P0/P1 都有独立 `P15-Fxx` 卡、最小修复、回归测试和提交；P2 有处理或延期理由。
- **允许文件**：每次只按一张修复卡范围；同步更新 review/state。
- **实现**：先复现失败测试，再修生产代码；禁止大范围无关重构；不得删除/放宽关键断言。
- **验证**：单项回归、相关阶段 Gate、diff check；记录 commit SHA。
- **负向**：修复不能引入 API 契约漂移；如确需变更先更新 ADR/契约并说明兼容。
- **完成门**：P0/P1 全部 CLOSED；延期项不影响 Must 闭环。

## P15-T06：重跑全部发布门并生成最终交付摘要

- **需求**：FINAL-01、REVIEW-01
- **前置**：P15-T05。
- **结果**：修复后重新执行 P14 全套，不复用修复前结果；生成最终 10 项项目总结和真实限制。
- **验证**：clean install、migration、backend tests/lint、frontend quality/build、E2E、persistence、Docker、secret scan、traceability；所有命令记录退出码和时间。
- **最终摘要必须含**：完成项、目录、架构、启动、OpenAI-compatible、Ollama、测试结果、限制、下一功能、可复用模块。
- **负向**：外部 live/Docker 未执行不得包装成成功；不得以“代码已完成”代替实际运行。
- **完成门**：`FINAL_REVIEW.md` 关闭重要问题；`EXECUTION_STATE.md` 无 NOT_STARTED/READY/IN_PROGRESS/BLOCKED 的 Must；最终 commit 仅含相关文件，不自动 push。
