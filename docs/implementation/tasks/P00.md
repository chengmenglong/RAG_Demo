# P00：基线与契约冻结

本阶段由实施文档编制者完成。后续 Luna 不应重做本阶段，只在发现明确冲突时创建文档修复任务。

## P00-T01：记录仓库与工具链基线

- **需求**：GOV-01
- **可观察结果**：任何后续代理都能知道项目起点、当前分支和已知环境限制。
- **范围**：只读仓库；更新 `00_MASTER_PLAN.md` 和 `EXECUTION_STATE.md`。
- **必须记录**：文件清单、Git 状态、最近提交、Python、Node、npm、Docker、Windows Python Launcher。
- **验证**：实际运行 `rg --files`、`git status --short --branch`、`git log -5 --oneline`、`python --version`、`node --version`、`npm --version`、`Get-Command docker -ErrorAction SilentlyContinue`。
- **负向检查**：未安装命令必须记为未发现，不得补写版本。
- **完成门**：事实带日期，未修改用户代码，命令结果与文档一致。

## P00-T02：冻结需求追踪矩阵

- **需求**：原始需求全部；GOV-02
- **可观察结果**：每个原始 Must 要求都有稳定 ID、实现阶段和验收证据类型。
- **范围**：`01_REQUIREMENTS_TRACEABILITY.md`。
- **必须做到**：覆盖产品、处理、RAG、引用、Chat、Settings、安全、日志、测试、Docker、Demo、README、复用、UI、验收、Review、最终报告。
- **验证**：搜索所有需求域 ID；逐节对照用户原文；不得把扩展清单误列为本次实现。
- **负向检查**：Mock、适配器合约和 live smoke 必须是三种不同证据。
- **完成门**：所有 Must 要求均有阶段映射，无无主需求。

## P00-T03：冻结架构与 ADR

- **需求**：ARC-01、ARC-02、CFG-01、DB-01、STORE-01
- **可观察结果**：后续任务不必重新选择框架、存储、任务方式或 Provider 结构。
- **范围**：`02_ARCHITECTURE_AND_ADRS.md`。
- **必须做到**：固定 React/Ant Design、FastAPI、同步 SQLAlchemy/Alembic、SQLite、Chroma PersistentClient、本地存储、BackgroundTasks、Provider/VectorStore 抽象、单 worker 和明确非目标。
- **验证**：架构文档包含依赖方向、运行拓扑、目录、ADR 状态、风险与升级路径。
- **负向检查**：不得同时保留两套“都可以”的核心技术选项。
- **完成门**：核心决策无歧义，替换边界明确。

## P00-T04：冻结 API、数据与业务不变量

- **需求**：DB-02、DOC-05、DOC-07、DOC-11、CIT-01、SET-03、SEC-01
- **可观察结果**：模型字段、状态、端点、响应、错误和 Citation 可由前后端共同实现。
- **范围**：`03_API_DATA_CONTRACTS.md`。
- **必须做到**：定义 UUID/UTC、页码 1-based、状态机、API 前缀、分页、错误 envelope、设置优先级、Embedding Profile、删除/重处理、Citation 快照。
- **验证**：逐一核对 CRUD、upload/reprocess/delete、chat、settings、dashboard、health；检查所有枚举只定义一次。
- **负向检查**：GET Settings 不得出现 Key 值字段；无命中响应不得包含伪 source。
- **完成门**：不存在“实现时再决定”的核心业务语义。

## P00-T05：建立 Luna 执行治理与验收门

- **需求**：GOV-01、GOV-02、TEST-04、REVIEW-01、FINAL-01
- **可观察结果**：上下文中断后，Luna 能从文件恢复唯一当前任务并提供真实证据。
- **范围**：`04_EXECUTION_PROTOCOL.md`、`05_ACCEPTANCE_GATES.md`、`EXECUTION_STATE.md`、`DECISIONS.md`、`FAILURE_LOG.md`、`tasks/`。
- **必须做到**：一个 `IN_PROGRESS`、原子任务、固定交接、失败升级、阶段门、本地提交、不自动 push。
- **验证**：检查所有 P00–P15 阶段都有任务文件；检查状态表中的任务 ID 与任务卡一致；运行 `git diff --check`。
- **负向检查**：任务卡不得使用 `TODO command`、`酌情完善` 或把未运行命令标 PASS。
- **完成门**：文档内部链接和 ID 一致，`NEXT_TASK` 唯一。
