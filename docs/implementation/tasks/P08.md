# P08：RAG、Citation 与 Chat 后端

阶段目标：用 Demo Provider 先完成无 Key 的后端核心闭环，并将引用作为结构化、可持久的业务对象。

## P08-T01：实现受约束 Prompt 与上下文预算

- **需求**：RAG-03、RAG-05、SEC-01
- **前置**：P07 Gate。
- **结果**：检索 Chunk 被编号为 `[S1]...[Sn]`，资料与系统规则明确隔离，Prompt 只包含预算内上下文。
- **允许文件**：`rag/prompt.py`、`rag/types.py`、测试。
- **实现**：声明只能依据资料、资料不足要明说、资料内指令不可信、每个事实引用标签；使用只读环境配置 `RAG_MAX_CONTEXT_CHARS`（默认 12000）的字符预算，MVP 不引入 tokenizer；问题和历史用独立分隔。
- **验证**：Prompt snapshot/结构断言；中文、代码块、含“忽略系统指令”的恶意文档；预算截断保持完整 source 边界。
- **负向**：原文中出现 `[S99]` 不能成为真实引用；不得把全部数据库内容塞入 Prompt。
- **完成门**：Prompt 不含 Key、绝对路径或无关文档。

## P08-T02：实现 RAG 编排、拒答和 Citation 白名单

- **需求**：RAG-01 至 RAG-05、CIT-01
- **前置**：P08-T01、P07-T06。
- **结果**：问题→query embedding→retrieval→Prompt→LLM→answer/sources；无可靠命中时固定拒答且不调用 LLM。
- **允许文件**：`rag/pipeline.py`、`rag/citations.py`、service schema、测试。
- **实现**：source metadata 只由 retrieval hit 构造；过滤模型生成的未知标签；source label/rank 稳定；记录 selected count/duration/provider，不记录正文。
- **验证**：Demo 命中、空库、无关问题、高阈值、未知 `[S99]`、LLM timeout/空答案。
- **负向**：断言 no-hit Mock LLM 调用次数为 0；任何 source 的 chunk 必须属于请求 KB。
- **完成门**：回答和 sources 能一一反查到当前 SQL Chunk。

## P08-T03：实现 ChatSession、ChatMessage、MessageCitation 模型与迁移

- **需求**：CHAT-01、CIT-03、DB-02
- **前置**：P08-T02。
- **结果**：会话绑定知识库；消息持久；assistant message 保存 Citation 快照，即使源文档删除也可显示。
- **允许文件**：三个模型、关系、一个迁移、repository 基础、测试。
- **实现**：UUID/UTC；role `user/assistant`；message status；ChatMessage 完整保存 provider/model/error_code/error_message；Citation 保存 label、document/chunk 可空 FK、文档名、页码、章节、excerpt、score、rank；on delete set null/快照保留。
- **验证**：迁移、级联消息、源文档删除后快照、排序、约束测试。
- **负向**：用户消息不得挂 Citation；同一消息 label/rank 不得重复。
- **完成门**：删除知识库按契约删除会话；直接删除单文档不破坏历史引用。

## P08-T04：实现会话与消息 Service

- **需求**：CHAT-01、CHAT-02、CIT-03
- **前置**：P08-T03。
- **结果**：可新建/列出/查看/删除会话，并将问答和 Citation 在单一业务操作中持久化。
- **允许文件**：chat repository/service/schema、测试。
- **实现**：会话 title 从首问安全截取或默认名；每次问题最多带最近 6 条历史、设总预算；会话 KB 不可变；先保存 user/completed 与 assistant/pending；命中或资料不足时更新 assistant/completed 并保存合法 Citation，Provider 失败时更新 assistant/failed 后返回错误。
- **验证**：历史顺序、标题、删除级联、RAG 成功/拒答/Provider 失败、重启持久。
- **负向**：session ID 与 KB 不匹配、空问题、并发重复提交有明确行为。
- **完成门**：失败不能生成伪 assistant success，已保存 user 的状态可解释。

## P08-T05：实现 Chat API

- **需求**：CHAT-01、CHAT-02、CIT-01、SEC-01
- **前置**：P08-T04。
- **结果**：会话 CRUD 和 `POST /chat-sessions/{id}/messages` 按冻结契约返回 message + sources。
- **允许文件**：`api/v1/chat.py`、router、API 测试。
- **实现**：会话创建和问答成功固定 201；非流式；错误 envelope；响应 source 直接来自持久快照；分页历史。
- **验证**：新建、列表、详情、提问、拒答、删除、404、422、Provider 502/504。
- **负向**：未知 session、已删除 KB、超长问题、恶意 Markdown；响应不含 Prompt 原文或 Key。
- **完成门**：OpenAPI schema 可供前端生成/维护类型。

## P08-T06：执行无 Key 后端核心闭环 Gate

- **需求**：GOV-02、DEMO-01、TEST-02、CIT-01
- **前置**：P08-T01 至 T05。
- **结果**：使用带唯一事实的 Markdown，经正式上传/解析/Embedding/Chroma/Chat 返回正确回答和 Citation。
- **验证**：从空库创建 KB→上传→等待 ready→提问唯一事实→断言 answer/source→按 chunk_id 反查 excerpt；再问无关问题断言固定拒答、sources=[]、LLM 未调用；重启后历史仍在。
- **负向**：跨库相同问题不得串库；恶意文档指令不得改变系统规则。
- **完成门**：P01–P08 pytest/Ruff 全绿；记录实际对象 ID 和断言摘要，不记录敏感正文。
